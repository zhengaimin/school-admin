# 权限系统手工演练流程

## 1. 演练目标

本文用于从超级管理员开始，手工创建平台角色、平台用户、代理商租户、租户管理员、组织部门和业务用户，并通过逐个登录账号理解功能权限与数据权限的关系。

| 项目     | 约定                                         |
| -------- | -------------------------------------------- |
| 数据前缀 | 所有演练数据使用 `QA-` 前缀                  |
| 统一密码 | `111111`                                     |
| 登录方式 | 建议使用无痕窗口，不勾选“记住账号及密码”     |
| 操作边界 | 只操作本文创建的 `QA-` 数据                  |
| 初始条件 | 已有可登录的超级管理员和后端预置的平台根租户 |

> 平台根租户不是通过当前“租户管理”页面创建的。页面会隐藏根租户，新增租户默认用于创建平台下属的代理商租户。

## 2. 核心关系

```text
超级管理员（系统预置）
└─ 平台根租户（后端预置）
   ├─ 平台角色 -> 平台用户 -> 管理被分配的代理商租户
   └─ 代理商租户
      ├─ 部门
      ├─ 代理商管理员角色 -> 代理商管理员用户
      └─ 业务角色 -> 业务员用户 -> 指定学校数据范围
```

| 概念     | 解决的问题           | 当前模型                                |
| -------- | -------------------- | --------------------------------------- |
| 租户     | 用户属于哪个业务主体 | 平台根租户下挂代理商租户                |
| 角色     | 用户能做什么         | 角色保存一组 `permissionIds`            |
| 用户     | 谁登录系统           | 用户绑定一个 `roleId` 和一个 `tenantId` |
| 组织架构 | 用户属于哪个部门     | 用户绑定一个 `orgDepartmentId`          |
| 数据权限 | 用户能看哪些数据     | 平台用户按租户，业务员按学校            |

标准依赖顺序：

```text
创建租户
  ├─ 创建部门
  └─ 创建角色
       └─ 创建用户
            ├─ 分配部门
            └─ 分配数据范围
```

## 10. 当前实现注意事项

| 事项           | 当前行为                                                         | 演练要求                           |
| -------------- | ---------------------------------------------------------------- | ---------------------------------- |
| 平台根租户     | 当前页面不创建且不展示                                           | 使用后端预置数据                   |
| 记住密码       | 会把原始密码写入本地存储                                         | 演练时不要勾选                     |
| 角色功能权限   | 由角色的 `permissionIds` 决定                                    | 不直接给用户分配功能权限           |
| 平台数据权限   | 使用 `TENANT` 范围                                               | 明确选择可管理租户                 |
| 业务员数据权限 | 使用 `SCHOOL` 范围                                               | 明确选择可管理学校                 |
| 代理商数据范围 | 页面不单独配置                                                   | 后端必须按用户租户隔离             |
| 组织架构       | 当前主要是扁平部门和用户归属                                     | 不把部门当作权限来源               |
| 用户分配部门   | 用户创建时不完成部门归属                                         | 创建后在组织架构中分配             |
| 子租户角色列表 | 平台账号不固定按平台根租户过滤，子租户可见范围由后端数据权限决定 | 平台账号创建后刷新列表确认角色可见 |
| 前端权限控制   | 菜单和按钮属于体验层                                             | 最终以接口 403 校验为准            |
