## 一、概述

### 1.1 你需要做什么？

作为前端开发，你需要处理以下三件事：

| 任务             | 说明                           | 难度 |
| ---------------- | ------------------------------ | ---- |
| **控制菜单显示** | 用户没有权限的菜单不显示       | 简单 |
| **控制按钮显示** | 用户没有权限的按钮隐藏或禁用   | 简单 |
| **处理403错误**  | 用户越权操作时，优雅地提示错误 | 简单 |

### 1.2 后端会给你什么？

登录成功后，后端返回的数据中包含：

```json
{
  "code": 0,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "user": {
      "id": 123,
      "username": "zhangsan",
      "realName": "张三",
      "roleCode": "agent_business",
      "tenantId": 2
    },
    "permissions": ["device:list", "device:create", "device:update", "student:list", "student:detail"]
  }
}
```

**重点关注 `permissions` 数组**，这就是用户拥有的所有权限码。

## 二、权限码是什么？

### 2.1 命名规则

权限码格式：`模块名:操作名`

| 权限码          | 含义     | 用途                       |
| --------------- | -------- | -------------------------- |
| `device:list`   | 设备列表 | 控制"设备管理"菜单是否显示 |
| `device:create` | 创建设备 | 控制"新增"按钮是否显示     |
| `device:update` | 编辑设备 | 控制"编辑"按钮是否显示     |
| `device:delete` | 删除设备 | 控制"删除"按钮是否显示     |
| `device:export` | 导出设备 | 控制"导出"按钮是否显示     |

### 2.2 常用操作名

| 操作名   | 含义      | 说明             |
| -------- | --------- | ---------------- |
| `list`   | 列表/查询 | 通常关联菜单显示 |
| `detail` | 详情      | 查看详情页面     |
| `create` | 新增      | 新增按钮         |
| `update` | 编辑      | 编辑按钮         |
| `delete` | 删除      | 删除按钮         |
| `export` | 导出      | 导出按钮         |
| `import` | 导入      | 导入按钮         |

### 2.3 完整权限码列表

向后端索取最新的权限码列表，或查看 `internal/middleware/permission_config.go` 文件。

## 三、需要对接的接口

权限系统涉及的接口按功能分类如下：

### 3.1 认证相关接口

| 接口                             | 方法 | 说明                       | 权限要求 |
| -------------------------------- | ---- | -------------------------- | -------- |
| `/admin/auth/login`              | POST | 用户登录                   | 无需认证 |
| `/admin/auth/logout`             | POST | 用户登出                   | 无需认证 |
| `/admin/auth/refresh`            | POST | 刷新Token                  | 无需认证 |
| `/admin/profile`                 | GET  | 获取当前用户信息和权限列表 | 需要登录 |
| `/admin/profile`                 | PUT  | 更新个人信息               | 需要登录 |
| `/admin/profile/change-password` | POST | 修改个人密码               | 需要登录 |

### 3.2 租户管理接口（超管/平台管理员使用）

| 接口                 | 方法   | 说明     | 权限码          |
| -------------------- | ------ | -------- | --------------- |
| `/admin/tenants`     | GET    | 租户列表 | `tenant:list`   |
| `/admin/tenants`     | POST   | 创建租户 | `tenant:create` |
| `/admin/tenants/:id` | GET    | 租户详情 | `tenant:list`   |
| `/admin/tenants/:id` | PUT    | 更新租户 | `tenant:update` |
| `/admin/tenants/:id` | DELETE | 删除租户 | `tenant:delete` |

### 3.3 角色管理接口

| 接口               | 方法   | 说明     | 权限码        |
| ------------------ | ------ | -------- | ------------- |
| `/admin/roles`     | GET    | 角色列表 | `role:list`   |
| `/admin/roles`     | POST   | 创建角色 | `role:create` |
| `/admin/roles/:id` | GET    | 角色详情 | `role:list`   |
| `/admin/roles/:id` | PUT    | 更新角色 | `role:update` |
| `/admin/roles/:id` | DELETE | 删除角色 | `role:delete` |

### 3.4 权限配置接口

| 接口                                          | 方法 | 说明                             | 权限码        |
| --------------------------------------------- | ---- | -------------------------------- | ------------- |
| `/admin/permissions/modules`                  | GET  | 获取权限模块列表（用于角色配置） | `role:list`   |
| `/admin/permissions/role-permissions/:roleId` | GET  | 获取角色已有的权限               | `role:list`   |

| `/admin/permissions/assign-role`              | POST | 给用户分配角色                   | `user:update` |

### 3.5 用户管理接口

## 五、前端实现步骤

### 5.1 存储权限列表

登录成功后，将权限列表存储到全局状态（如 Vuex/Pinia/Redux）：

```javascript
// store/user.js (Pinia 示例)
import { defineStore } from "pinia";

export const useUserStore = defineStore("user", {
  state: () => ({
    token: "",
    userInfo: null,
    permissions: [] // 权限码列表
  }),

  actions: {
    // 登录成功后调用
    setLoginData(data) {
      this.token = data.token;
      this.userInfo = data.user;
      this.permissions = data.permissions || [];

      // 持久化存储
      localStorage.setItem("token", data.token);
      localStorage.setItem("permissions", JSON.stringify(this.permissions));
    },

    // 页面刷新后恢复
    restoreFromStorage() {
      this.token = localStorage.getItem("token") || "";
      const stored = localStorage.getItem("permissions");
      this.permissions = stored ? JSON.parse(stored) : [];
    }
  },

  getters: {
    // 检查是否有某个权限
    hasPermission: state => code => {
      // 如果没有权限列表，可能是超级管理员（拥有所有权限）
      if (state.userInfo?.roleCode === "super_admin") {
        return true;
      }
      return state.permissions.includes(code);
    },

    // 检查是否有多个权限中的任意一个
    hasAnyPermission: state => codes => {
      if (state.userInfo?.roleCode === "super_admin") {
        return true;
      }
      return codes.some(code => state.permissions.includes(code));
    }
  }
});
```

### 5.2 创建权限指令（Vue）

创建一个自定义指令，方便在模板中使用：

```javascript
// directives/permission.js
import { useUserStore } from "@/store/user";

export const permission = {
  mounted(el, binding) {
    const userStore = useUserStore();
    const { value } = binding;

    if (value) {
      const hasPermission = Array.isArray(value) ? userStore.hasAnyPermission(value) : userStore.hasPermission(value);

      if (!hasPermission) {
        // 没有权限，移除元素
        el.parentNode?.removeChild(el);
      }
    }
  }
};

// main.js 中注册
app.directive("permission", permission);
```

**使用方式：**

```vue
<!-- 单个权限 -->
<el-button v-permission="'device:create'">新增设备</el-button>

<!-- 多个权限（满足任意一个即可） -->
<el-button v-permission="['device:update', 'device:delete']">操作</el-button>
```

### 5.3 创建权限组件（可选）

如果你喜欢组件方式：

```vue
<!-- components/Permission.vue -->
<template>
  <slot v-if="hasPermission"></slot>
</template>

<script setup>
import { computed } from "vue";
import { useUserStore } from "@/store/user";

const props = defineProps({
  code: {
    type: [String, Array],
    required: true
  }
});

const userStore = useUserStore();

const hasPermission = computed(() => {
  if (Array.isArray(props.code)) {
    return userStore.hasAnyPermission(props.code);
  }
  return userStore.hasPermission(props.code);
});
</script>
```

**使用方式：**

```vue
<Permission code="device:delete">
  <el-button type="danger">删除</el-button>
</Permission>
```

```javascript
/**

 */
export function filterMenusByPermission(menus) {
  const userStore = useUserStore();

  return menus.filter(menu => {
    // 没有配置权限的菜单，所有人可见
    if (!menu.permission) {
      return true;
    }

    // 检查是否有权限
    if (!userStore.hasPermission(menu.permission)) {
      return false;
    }

    // 递归处理子菜单
    if (menu.children && menu.children.length > 0) {
      menu.children = filterMenusByPermission(menu.children);
      // 如果子菜单全部被过滤掉，父菜单也不显示
      return menu.children.length > 0;
    }

    return true;
  });
}
```

## 八、处理403错误

当用户越权操作时，后端会返回 `403` 状态码。你需要在全局响应拦截器中处理：

```javascript
// utils/request.js
import axios from "axios";
import { ElMessage } from "element-plus";
import { useUserStore } from "@/store/user";
import router from "@/router";

const request = axios.create({
  baseURL: "/api",
  timeout: 10000
});

// 响应拦截器
request.interceptors.response.use(
  response => response.data,
  error => {
    const { response } = error;

    if (response) {
      switch (response.status) {
        case 401:
          // Token 过期或无效
          ElMessage.error("登录已过期，请重新登录");
          const userStore = useUserStore();
          userStore.logout();
          router.push("/login");
          break;

        case 403:
          // 权限不足
          ElMessage.error(response.data?.message || "您没有权限执行此操作");
          break;

        case 404:
          ElMessage.error("请求的资源不存在");
          break;

        case 500:
          ElMessage.error("服务器错误，请稍后重试");
          break;

        default:
          ElMessage.error(response.data?.message || "请求失败");
      }
    } else {
      ElMessage.error("网络错误，请检查网络连接");
    }

    return Promise.reject(error);
  }
);

export default request;
```

### 8.1 常见的403错误信息

| 错误信息                         | 原因                           | 解决方案               |
| -------------------------------- | ------------------------------ | ---------------------- |
| `"用户已禁用，请联系管理员"`     | 账号被管理员禁用               | 联系管理员启用账号     |
| `"用户角色已禁用，请联系管理员"` | 角色被禁用                     | 联系管理员处理         |
| `"无权限访问该接口"`             | 角色没有该API权限              | 联系管理员分配权限     |
| `"无权限查看该学校的数据"`       | 数据范围不包含该学校           | 联系管理员扩大数据范围 |
| `"无权限操作该用户"`             | 越级操作（如业务员修改管理员） | 这是正常限制，无法操作 |

## 九、特殊角色处理

### 9.1 超级管理员

超级管理员（`roleCode === 'super_admin'`）拥有所有权限，不需要检查权限码：

```javascript
// 在 hasPermission 中处理
hasPermission(code) {
  // 超级管理员拥有所有权限
  if (this.userInfo?.roleCode === 'super_admin') {
    return true
  }
  return this.permissions.includes(code)
}
```

### 9.2 平台管理员 vs 代理商管理员

这两种角色的区别主要在**数据范围**，前端不需要特殊处理。后端会自动过滤数据：

- **平台管理员**：可以看到所有租户的数据
- **代理商管理员**：只能看到自己租户的数据

前端只需要正常调用接口，后端会返回已过滤的数据。

## 十一、常见问题

### Q1: 权限码从哪里获取？

登录接口返回的 `permissions` 数组就是当前用户的权限码列表。

### Q2: 菜单配置中的 permission 填什么？

通常填写该模块的 `list` 权限，例如设备管理菜单填 `device:list`。具体权限码请查看后端提供的权限码列表。

### Q3: 用户没有任何权限怎么办？

如果 `permissions` 数组为空：

- 可能是超级管理员（后端不返回权限列表，但拥有所有权限）
- 可能是角色没有配置任何权限（显示空菜单）

建议检查 `roleCode`，如果是 `super_admin` 则显示所有内容。

### Q4: 权限修改后需要重新登录吗？

**不需要**。后端采用实时校验机制，权限修改后立即生效。但前端存储的 `permissions` 列表不会自动更新，如果需要实时更新菜单，可以：

1. 刷新页面（重新调用登录接口获取最新权限）
2. 或者定时轮询获取最新权限

### Q5: 为什么按钮隐藏了，但直接调接口还是报403？

**这是正确的！** 前端隐藏按钮只是为了用户体验，真正的权限控制在后端。即使绕过前端直接调接口，后端也会拦截。这是"双重保障"的安全设计。

### Q6: 不同租户的用户看到的数据不一样，前端需要处理吗？

**不需要**。数据过滤完全由后端处理，前端只需要正常调用接口，后端会自动返回该用户有权限看到的数据。
